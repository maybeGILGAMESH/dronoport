# Сеть дронопортов России — вариант И

Исследовательский проект для Московской, Смоленской и Тверской областей; буквы ЖЗИКЛ.
10 мест, дальность 200 км между зарядками, три ежегодных транша по 1 млрд рублей с переносом остатка.
Население и координаты имеют источники; спрос, технические параметры и цены — учебные допущения.

## Дополнение CP-SAT и генетический алгоритм

Исходный опубликованный расчёт `20261105_181440_v2` и его ZIP сохранены. Дополнение
создаёт отдельный запуск: CP-SAT оптимизирует расписание при фиксированных портах,
покупках и базах аппаратов; затем GA и новый отжиг сравниваются на одном CP-декодере.
Полный CP использует все допустимые рейсы временной сетки. Быстрый декодер использует
объединение трёх конструктивных расписаний и допустимого старта: его граница относится
только к этому пулу рейсов. Предел виртуальной памяти одного CP-процесса — 20 ГиБ.

В историческом отчёте версии CP-SAT сначала приведено дополнение, затем сохранённое базовое исследование. Текущий reports/report.pdf объединяет результаты в связную сравнительную статью.
`reports/maps/network.html` показывает исходную сеть,
`reports/maps/network_cp_ga.html` — лучший план дополнительного поиска.
`reports/optimized_investments.csv` содержит его покупки, а исходные инвестиции остаются
в каталоге запуска. Обе карты автономны; переносить вместе с `maps/assets`.

Повтор численного эксперимента выполняется в новой копии, а не поверх опубликованной:

```bash
.venv/bin/python scripts/create_cp_ga_run.py --baseline runs/ИМЯ_БАЗОВОГО_ЗАПУСКА
.venv/bin/python scripts/run_fixed_cpsat.py
.venv/bin/python scripts/refine_cpsat_portfolio.py
.venv/bin/python scripts/run_evolution_experiment.py --seconds 600 --seeds 10 --workers 10
.venv/bin/python scripts/check_search_best_scenarios.py
```

Скрипт создания выводит новый путь; остальные используют сохранённый рабочий указатель.
Явный выбор доступен через `--run-dir`. Для пересборки из готовых результатов:
`.venv/bin/python scripts/run_project.py --report-only --run-dir runs/ИМЯ_ЗАПУСКА`.
Последний сценарный этап автоматически устанавливает статус численного запуска `calculated`.
Проверки дополнения: `scripts/validate_cp_ga.py --run-dir runs/ИМЯ_ЗАПУСКА`;
общие проверки: `scripts/check_delivery_consistency_v2.py --run-dir runs/ИМЯ_ЗАПУСКА`.
Браузерную проверку выполнить для обеих карт, сохранив результаты в `report/browser_checks`
и `report/browser_checks_cp_ga` соответственно. Упаковка: `scripts/publish_v2.py --run-dir ...`.

Поиск идёт на 30 пунктах, по 10 парных seed и 600 секунд на каждый метод/seed. При
параллельной работе время включает конкуренцию за ресурсы. CP использует отдельный процесс,
чтобы не смешивать нативные библиотеки HiGHS и OR-Tools. Прерванная серия продолжает
завершённые seed; точные планы и истории сохраняются. Исходники каждого этапа находятся
в `cp_ga/source_snapshot_*`. Полный CP при фиксированной сети не доказывает оптимальность
выбора сети; GA и отжиг дают допустимые нижние оценки.

## Версии и результаты

Версия `v2` использует свободные ротации аппаратов, временную сетку 10 минут,
пересадки по всем путям расписания и реальные межгодовые перегоны. Полная зарядка после каждого
рейса остаётся явным допущением. Два зарядных места и два движения суммарно за каждый
фиксированный 90-минутный интервал учитываются отдельно.

- `results_v2/current_run.txt` указывает каталог актуального расширенного запуска.
- `runs/<run_id>_v2/` содержит все планы, конфигурации, проверки, эксперименты и снимок кода.
- `reports/report.pdf`, `reports/report.html`, `reports/maps/network.html` — опубликованный комплект после проверки.
- `reports/requirements_matrix.csv` показывает выполнение каждого пункта и ограничения.
- `results/` и `artifacts/preserved_20261105_171655/` относятся к прежней коридорной версии `v1`.
  Старый PDF и ZIP сохранены неизменными.

## Запуск

Из корня проекта, Python 3.12:

```bash
bash scripts/bootstrap.sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/run_project.py --model-version v2 --experiments full
```

По умолчанию запускается `v2`. Полная серия включает 40 запусков отжига, бюджетную сетку,
чувствительность, стресс-тесты, MIP и последовательные MIP. MIP имеет лимит 1800 секунд
на решение; каждый запуск отжига использует 600 секунд (`annealing_iterations: 0`
означает остановку по времени). Полная последовательная серия может занять более 9 часов. CUDA не требуется.

```bash
# Короткий технический прогон; НЕ полный комплект экспериментов
.venv/bin/python scripts/run_project.py --model-version v2 --experiments quick --solver-seconds 30

# Продолжение прерванной серии: сохранённые seed и эксперименты перепроверяются
.venv/bin/python scripts/run_project.py --model-version v2 --experiments full --resume

# Пересборка отчёта из текущего расширенного запуска
.venv/bin/python scripts/run_project.py --report-only

# Сохранённая прежняя модель
.venv/bin/python scripts/run_project.py --model-version v1
```

Опции: `--seed` задаёт начало последовательности seed, `--solver-seconds` — лимит MIP,
`--run-dir` выбирает каталог для пересборки/продолжения; `--skip-mip` явно помечает пропуск решателя.
Обновления кода после расчёта не изменяют исходный `source_snapshot` численного запуска.
При продолжении создаётся отдельный снимок кода в `source_snapshots/`, предыдущий
манифест сохраняется; времена ранее завершённых вычислений не заменяются временем чтения файлов.

В опубликованном запуске предварительная серия из 200 итераций сохранена в
`preliminary_iteration_study/`. Дополнительная серия по 600 секунд выполнена 16 процессами;
её точный код, времена и результаты находятся в `time_budget_study/`.
Конкуренция процессов влияет на измеренное время, поэтому сумма времён серии и время
одного запуска приведены отдельно. Первые MIP использовали начальные решения предварительной серии;
завершающие попытки на 20/30 пунктах получили полный допустимый старт после доработки размещения.
Скрипты дополнительных этапов: `run_timed_seeds_v2.py`, `promote_timed_seeds_v2.py`,
`refine_recourse_v2.py`. Их нельзя повторять поверх запечатанного комплекта.

## Подготовка данных

Текущие 30 и 8 пунктов зафиксированы до расширенной оптимизации. Для пересчёта экспериментов
достаточно `data/processed/`; большой OSM PBF для этого не нужен.

```bash
# Восстановление исходного извлечения и фиксированного отбора
.venv/bin/python scripts/prepare_data.py

# Дополнение полигонами поселений, пространственная дедупликация
.venv/bin/python scripts/audit_registry_v2.py

# Официальный перечень ФНС: выборочная загрузка XML трёх областей через HTTP Range
.venv/bin/python scripts/audit_gar_v2.py
```

`data/processed_v2/registry_gar.csv` сохраняет все действующие поселения нужных букв
в опубликованном ГАР по явно заданным уровням и типам. Города на административном уровне 2
включаются; муниципальные образования, дороги и территории не принимаются за поселения.
Неоднозначные совпадения с OSM остаются неразрешёнными. Полнота официального списка
не означает полноту географического сопоставления. Пропуски населения не заполняются.

Источники и хэши: `data/processed_v2/gar_sources.json`, `gar_audit.json`, `polygon_audit.csv`.
Росстат: таблица 5 ВПН, дата населения 01.10.2021; сельские пункты в этой таблице — от 3000 жителей.
OSM: экстракт от 03.11.2026. ГАР: опубликованная версия 03.11.2026.

Новая HTML-карта работает через `file://` и без интернета. Leaflet сохранён локально;
границы и данные встроены. Внешней дорожной подложки нет, поэтому блокировка OSM 403

## Как читать результаты

- `method_comparison.csv`, `seed_results.csv`, `search_history.csv` — методы и все seed.
- `mip_reports.json` — статус, лимит, допустимое значение и граница временного MIP.
- `aggregate_bounds.json` — верхние границы непрерывной агрегированной релаксации, **не расписания**.
- `experiments.csv` — бюджеты 250–1000 млн и чувствительность.
- `scenario_results.csv` — фиксированные активы, изменение спроса/дальности и отказы портов.
- `base/`, `robust/`, `scale/`, `sequential_mip/`, `scenarios/` — планы, расписания и проверки.
- `report/figure_manifest.json` связывает каждый рисунок с исходными CSV/JSON.
- `MODEL_V2.md` содержит развёрнутую математическую постановку и область действия границ.
- `examples/` содержит проверяемую пересадку со сменой аппарата и пример порожнего возврата.
- `experiments_raw.csv` и `experiments_portfolio/` разделяют первичный поиск и дополнительные допустимые кандидаты.

MIP может остановиться по времени или защите размера матрицы. Это явно записывается;
нельзя считать такой запуск доказанным оптимумом. Робастный поиск и восстановление перевозок
эвристические. Сравнения по seed описательные; ANOVA без обоснованного дизайна не применяется.
Тарифы и наземная конкуренция не моделируются. Короткие городские связи не являются рекомендацией
реального пассажирского авиасервиса.

Дополнительная попытка полной временной модели с ограничением виртуальной памяти:
`.venv/bin/python scripts/attempt_large_mip_v2.py --nodes 20 --memory-gib 5 --tag _new`.
Она пишет отдельные результаты и журнал, включая отказ выделения памяти; исходный запуск
не перезаписывается. Сведение завершённых попыток: `scripts/integrate_large_mip_v2.py`.
В сборке матрицы отбрасываются только дуги, заведомо несовместимые с возвращением аппарата
на базу до конца суток; допустимое множество модели от этого не сужается.

Основные параметры: `config/model.yaml` + `config/expanded.yaml`.
Зависимости закреплены в `requirements.txt`. Независимый валидатор пересчитывает физические
и денежные ограничения по экспортированным артефактам, а не по матрицам решателя.

Дополнительные этапы опубликованного исследования сохраняют собственные снимки кода и манифесты:
`deployment_polish/` — удаление неиспользуемых портов и проверка новых приобретений;
`extended_mip_attempts/` — ограниченные по памяти полные MIP;
`sequential_mip/8/constructive_start_revision.json` — улучшение старта третьего года при неизменных
первых двух годах. После изменения основного плана повторяются `refine_recourse_v2.py`,
`include_deployment_budget_v2.py` и `build_examples_v2.py`, затем отчёт и проверки.
Измеренный по времени отжиг не обещает побитового совпадения на другом оборудовании;
для точного аудита сохранены результаты, seed, конфигурации и исходники каждого этапа.

Последнее дополнение: **порт и фактические рейсы в каждой области к третьему году**.
Для варианта И это Московская, Смоленская и Тверская области (PDF задания, с. 4).
Это дополнительное условие пользователя: исходное задание на с. 3 разрешает не строить
порт в каждом регионе. Итоговая карта — `reports/maps/network_regional.html`,
инвестиции — `reports/regional_investments.csv`, новый раздел стоит первым в `reports/report.pdf`.
Прежние эксперименты в отчёте сохранены и обозначены как расчёты без нового ограничения.

Численные результаты находятся в `regional/` нового запуска, ссылка на опубликованный
запуск хранится в `results_v2/current_run.txt`. Для воспроизведения регионального поиска:
`scripts/run_regional.py` копирует текущий опубликованный запуск, сохраняет его активы
и добавляет два порта третьего года; перебирает замкнутые маршруты, затем улучшает
расписание CP-SAT. `scripts/refine_regional.py` повторяет CP-SAT и распределение пассажиров;
`scripts/refine_regional_scenarios.py` улучшает стресс-сценарии. Последний скрипт запускают
один раз: он сохраняет исходные сценарии и отказывается их перезаписывать.
Все команды выполняются через `.venv/bin/python`. Рабочий новый каталог записывается
в `.cache/regional_run.txt`; опубликованный указатель меняется только при сборке комплекта.
Глобальная оптимальность инвестиций не заявляется; GA и отжиг в региональной постановке
заново не сравнивались. Ограничение числа рейсов относится к базовому режиму; в стрессах
сохранены построенные активы, а региональный минимум обслуживания не гарантируется.
Проверка дополнения: `scripts/validate_regional.py --run-dir runs/<идентификатор>`;
пересборка PDF: `scripts/run_project.py --report-only --run-dir runs/<идентификатор>`.
