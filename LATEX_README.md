# LaTeX-редакция и автономные карты

Основной документ: `reports/report.pdf`. Исходник: `reports/latex/report.tex`. HTML с формулами MathML и теми же пояснениями: `reports/latex/report.html`. Детальная карта: `reports/latex/maps/index.html`.

Редакция содержит 14 формул с разделами «Где» и 75 пояснениями обозначений, 26 аналитических рисунков с объяснением абсцисс, ординат, единиц и интерпретации, а также 25 снимков сетей. Сохранены матрица всех 28 требований, три частично закрытых пункта и исходные численные результаты.

## Что изображено на картах

- A, B и C: обзор и подробная сеть для каждого из трёх лет, 18 видов.
- Ранняя коридорная модель: подробная сеть каждого года, 3 вида.
- Региональный вариант C: московское ядро, Кардымово и Зубцов в третьем году, 3 вида.
- Наложение A/B/C в третьем году, 1 вид.

Снимки для PDF находятся в `reports/latex/screenshots/chromium_offline`. Снимки через локальный сервер и проверки Firefox сохранены рядом. Манифесты `screenshots_manifest.json`, `map_validation.json` и `map_local_server_validation.json` связывают виды с файлами и контрольными суммами.

Используется локальная выгрузка OSM от 03.11.2026: дороги, железнодорожные линии, реки, замкнутые водные объекты и названия поселений. Это собственный светлый рендер избранных объектов, а не полный стиль OSM Carto. Здания и составные водные отношения не отрисованы. Границы извлечения охватывают три области полностью. Данные распространяются с атрибуцией OpenStreetMap и лицензией ODbL; изменённая база в `data/cartography/basemap.json.gz` включена в комплект.

Цветные связи показывают фактические рейсы модели, а не дороги или разрешённые авиационные трассы. На общих видах близкие московские порты объединены одной подписью; при увеличении подписан каждый порт. В автономном режиме гарантированы сохранённые виды и масштабы. Для новых масштабов можно запустить локальный сервер, который отрисует дополнительные тайлы из сохранённой базы без интернета.

## Последовательная сборка без интернета

Из корня проекта в уже подготовленном окружении:

```bash
unshare -Urn .venv/bin/python scripts/rebuild_latex_offline.py --offline --network-namespace
```

Команда выполнена при подготовке комплекта. `unshare -Urn` создаёт отдельное сетевое пространство Linux, в котором нет внешних сетевых интерфейсов. Скрипт последовательно проводит аудит семи каталогов расчётов, подготавливает слои, снимает 25 видов в Chromium и Firefox, компилирует LaTeX только из кэша и проверяет PDF, формулы и HTML. Оптимизаторы не запускаются. Системные сети и другие процессы не отключаются.

Если пользовательские пространства имён Linux недоступны, используется:

```bash
.venv/bin/python scripts/rebuild_latex_offline.py --offline
```

В этом случае отключение сети проверяется на уровне браузеров, а Tectonic работает с `--only-cached`; изоляция сети ядром не заявляется.

Для первого восстановления Python-окружения из архива нужен интернет либо заранее скачанные wheel-пакеты:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-latex.txt
.venv/bin/python -m playwright install firefox
chmod +x .tools/tectonic
```

Нужен установленный Chrome по пути `/usr/bin/google-chrome`. При другой установке измените путь в скриптах проверки и съёмки. После установки зависимостей повторная сборка выполняется без сети.

## Локальный сервер OSM

```bash
.venv/bin/python scripts/serve_local_osm.py --port 8765
```

Откройте `http://127.0.0.1:8765/index.html`. Сервер доступен только с этой машины. Он не обращается к публичным серверам тайлов и не требует VPN. Остановка: Ctrl+C.

Последовательная подготовка новых локальных тайлов, снимков и PDF:

```bash
.venv/bin/python scripts/rebuild_latex_offline.py
```

Скрипт сам запускает временный сервер, делает снимки, останавливает сервер, проверяет карты без сети и компилирует документ. Готовая база OSM включена в архив, повторное чтение большого PBF не требуется. Если база удалена, для её восстановления потребуется исходный `central-fed-district-261103.osm.pbf` с контрольной суммой из `data/cartography/provenance.json`.

Только пересборка PDF и HTML:

```bash
.venv/bin/python scripts/build_latex_report.py
.venv/bin/python scripts/check_latex_report.py --browsers
```

## Компилятор, шрифты и воспроизводимость

Tectonic 0.17.0 для Linux x86_64 находится в `.tools/tectonic`; необходимые пакеты TeX в `.tools/tex-cache`, шрифты DejaVu в `reports/latex/fonts`. Источники и лицензии сохранены. Tectonic использует XeTeX/LaTeX и не заменяет вёрстку растровыми снимками формул. В HTML формулы представлены локальным MathML, без CDN и MathJax-запросов.

При первичном наполнении кэша использовался официальный пакет TeX `https://data1.fullyjustified.net/tlextras-2022.0r0.tar`. Адрес `127.0.0.1:18766` в параметре bundle обозначает идентификатор первоначального локального транспорта. При `--only-cached` сервер на этом адресе не нужен: финальная сборка выполнена после его остановки в пространстве без сети. `scripts/tectonic_bundle_proxy.py` нужен только для первоначального наполнения кэша; он не входит в обычную цепочку пересборки.

`build_manifest.json` фиксирует исходники и PDF, `validation.json` проверки документа, `pipeline_validation.json` порядок шагов и сетевую изоляцию. Временные метки PDF могут меняться между сборками; сравниваются текст, TeX, численные данные и контрольные суммы входов.

## Сохранённые решения

Объединённый архив содержит исходные комплекты A, B, C и раннюю коридорную версию без изменений. Рабочие вычисления находятся в `runs/20261106_154352_regional`. Предыдущая статья с 18 рисунками сохранена в `reports/article`, исторические отчёты в исходных комплектах.

Новая вёрстка не устраняет три вычислительных ограничения: неполное сопоставление координат официального реестра, остановку полной MIP на 30 пунктах по памяти и отсутствие завершённого сравнения совместного и последовательного MIP на этом размере. Они остаются явно отмеченными в отчёте.

Подробности аудита и новые диагностические выводы: [RESEARCH_AUDIT_README.md](RESEARCH_AUDIT_README.md). Полная перепроверка архивных данных: `.venv/bin/python scripts/audit_research.py`. Численные оптимизаторы эта команда не запускает.
